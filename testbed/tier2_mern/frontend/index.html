ℹ️ What makes this server vulnerable?
This server intentionally omits the X-Content-Type-Options: nosniff response header when serving files from /uploads/. An uploaded PNG+HTML polyglot file (with a valid PNG magic header but HTML/JS payload embedded later in the file) may be executed as HTML by a browser that performs MIME sniffing. Additionally, the background archive worker processes the same file with adm-zip and is vulnerable to Zip-Slip path traversal when a ZIP trailer is appended after the PNG header.

🔬 Attack Vectors & PolyMorph Commands Lab Reference
VECTOR 1 Stored XSS via MIME Sniffing (PNG + HTML Polyglot)

Build an image containing an HTML script payload injected inside a PNG tEXt chunk: 

python -m PolyMorph build sample.png xss.html -A png -B html -s inject -o tier2_xss.png
Trigger: Upload tier2_xss.png above → open http://localhost:3001/uploads/avatar_<ts>.png directly in your browser.
Why it works: Express serves the file with Content-Type: image/png but deliberately omits X-Content-Type-Options: nosniff. The browser content-sniffs, finds <script>, and executes the JS payload.
VECTOR 2 Parser Differential & Zip-Slip (PNG + ZIP Polyglot)

Build a dual-valid file: passes image magic-byte validation at offset 0, but terminates with a valid ZIP central directory: 

python -m PolyMorph build sample.png zip_slip.zip -A png -B zip -o tier2_zip.png
Trigger: Upload tier2_zip.png above → background worker processes it via adm-zip.
Why it works: file-type reads the PNG header and accepts the upload. 500ms later, the archive worker opens the file from the tail (EOCD marker) and unpacks pwned_tier2.txt into extracted/. Check server logs or the extracted/ directory.
